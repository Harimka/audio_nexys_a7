# MicroLab в USB HOST → восьмиразрядный индикатор

Это отдельная пассивная диагностическая прошивка Nexys A7-100T. Она наблюдает доступные FPGA линии PIC24 `PS2_CLK` (F4) и `PS2_DATA` (B2), но не является USB-MIDI host. Никаких команд в PIC24/MicroLab не посылает, PIC24 не перепрошивает. Звук намеренно выключен. Рабочие исходники звукового демо в `src/top` не меняются.

## 1. Собрать на Ubuntu с Vivado

Распаковать ZIP целиком. Из корня распакованного `audio_nexys_a7` выполнить:

```bash
vivado -mode batch -source diagnostics/usb_host_probe/build.tcl
```

Если Vivado запускается только из ярлыка: открыть Vivado, внизу вкладку **Tcl Console**, выполнить (подставить фактический путь):

```tcl
source /home/user/audio_nexys_a7/diagnostics/usb_host_probe/build.tcl
```

Скрипт создаёт **отдельный** проект в `build/usb_host_probe`; синтезирует, выполняет implementation и генерирует bitstream. Исходный проект `vivado/` не перезаписывается. Если диагностический проект уже существует, скрипт остановится: открыть `build/usb_host_probe/usb_host_probe.xpr`, затем повторно запустить нужные runs в GUI либо переместить старый каталог build/usb_host_probe перед повторной сборкой.

Результат успешной сборки:

```text
build/usb_host_probe/usb_host_probe.runs/impl_1/audio_nexys_a7.bit
```

Локально у помощника Vivado нет: этот bitstream **не собран**, Vivado DRC/timing/CDC ещё не проверены. Скрипт сохраняет соответствующие reports в `build/usb_host_probe`; проверить их после сборки. Icarus не заменяет эти проверки.

## 2. Подключить и прошить

1. Плата подключена к ноутбуку кабелем в **PROG/UART**, питание платы включено.
2. MicroLab кабелем USB-C→USB-A подключён в **USB HOST J5 платы**, не ноутбука. Проверить питание MicroLab.
3. В Vivado: **Open Hardware Manager → Open Target → Auto Connect**.
4. **Program Device**, выбрать именно новый `.bit` по пути выше, затем **Program**. Не выбирать старый bitstream звукового проекта.
5. Кратко нажать **CPU RESET** на плате, чтобы очистить диагностические счётчики. Не путать с кнопкой **PROG**, которая сбрасывает FPGA-конфигурацию. После CPU RESET приём запускается примерно через 10,5 мс.
6. Для начала оба самых правых переключателя **SW0 и SW1 вниз** (0); остальные переключатели этой диагностикой не используются.

## 3. Страницы восьми цифр

Все позиции читаются слева направо. SW0 — крайний правый переключатель, SW1 — следующий слева. Вверх=1, вниз=0.

| SW1 | SW0 | Что показывает |
|---|---|---|
| вниз | вниз | `CCCC PP BB`: число корректных PS/2 кадров (4 hex цифры), предпоследний и последний байт (по 2 hex) |
| вниз | вверх | `EEEE FF TT`: число спадов clock (4 hex), число ошибок start/parity/stop (2 hex), тайм-ауты неполного кадра (2 hex) |
| вверх | вниз | `G C NNN VVV`: попытка MIDI-интерпретации принятых байтов; G=1 при активной ноте, C=канал 0…F, NNN=номер ноты в десятичном виде, VVV=velocity в десятичном виде |
| вверх | вверх | `12345678`: самотест индикатора, работает без MicroLab |

Hex — шестнадцатеричные цифры 0…9,A,b,C,d,E,F. Например, `0003 30 24` означает три корректных кадра, последние байты 0x30 и 0x24. Это **ещё не доказательство трёх нот**.

Если контроллер действительно передаст MIDI как последовательность PS/2 payload-байтов `90 30 24`, на MIDI-странице будет `1 0 048 036`. После `80 30 39` — `0 0 048 000`. Такой формат от реального PIC24 пока не установлен: эти примеры проверены только синтетическим тестом. Обычные клавиатурные scan codes не являются номерами MIDI-нот; случайное совпадение байтов с MIDI не доказывает поддержку MicroLab.

Счётчики насыщаются: кадры/спады на FFFF, ошибки/тайм-ауты на FF. CPU RESET очищает все счётчики, историю и попытку MIDI-интерпретации. Нота монофоническая: последнее нажатие, отпускание совпадающего канала и номера; старые удерживаемые ноты не восстанавливаются.

## 4. Светодиоды

- LED15 мигает с полным периодом примерно 0,67 секунды: FPGA/clock работают.
- LED14 — текущий отфильтрованный уровень clock; LED13 — data. При стандартном idle ожидаются единицы.
- LED12 — после reset замечено изменение clock; LED11 — изменение data.
- LED10 — после reset принят хотя бы один корректный PS/2 кадр.
- LED9 — замечена ошибка кадра; LED8 — тайм-аут неполного кадра.
- LED7…LED0 — последний корректный байт двоичным числом.

Активность отмечается после 2-FF синхронизации и фильтра примерно 80 нс; более короткие импульсы не фиксируются. Отсутствие активности не означает, что MicroLab вообще не передаёт USB: наблюдается выход PIC24 к FPGA, а не сами D+/D− USB. Другая схема передачи/firmware не обязана соответствовать PS/2.

## 5. Что сделать на стенде

1. Включить самотест SW1=SW0=вверх: убедиться, что читается `12345678`, LED15 мигает.
2. Перевести оба вниз, нажать CPU RESET. Записать исходное значение и LED14/13.
3. Нажать/отпустить одну клавишу MicroLab пять раз, затем другую пять раз. Сфотографировать default-страницу.
4. Перевести только SW0 вверх и сфотографировать страницу clock/errors/timeouts.
5. Проверить MIDI-страницу (SW1 вверх, SW0 вниз), записать реакцию; не объявлять её нотами без сопоставления с конкретными нажатиями.
6. Если нет реакции: оставить диагностику запущенной, переподключить MicroLab к J5, записать события при подключении отдельно от событий клавиш. После подключения снова CPU RESET и повторить нажатия.
7. Если доступна обычная USB Boot HID клавиатура, использовать её как положительный контроль. В имеющемся комплекте она не подтверждена.

Если self-test работает, а clock/frames не меняются, получен результат «на наблюдаемых линиях событий при этом эксперименте нет». Это не окончательный вывод о firmware, USB питании/перечислении или невозможности всех способов подключения. Если edges растут, а frames нет — сфотографировать ошибки/тайм-ауты, протокол ещё не установлен.

## Проверки исходников

```bash
python3 tests/probe/run_probe_tests.py
```

Проверены в Icarus: idle, подавление короткого glitch, start/odd parity/stop, неполный кадр и recovery после timeout, счётчики/история, LED, сканирование всех 8 цифр и самотест, страницы, synthetic MIDI On/Off, CPU RESET, отсутствие аудиовыхода. Реальные PIC24/MicroLab не симулируются.
