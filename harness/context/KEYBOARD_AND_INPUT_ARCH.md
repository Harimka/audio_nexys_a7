# АРХИТЕКТУРА ВВОДА: ОБЫЧНАЯ КЛАВИАТУРА (USB HID / PS/2) И МОДУЛЬНЫЕ ДРАЙВЕРЫ

Этот документ фиксирует смену концепции ввода: **вместо редкой MIDI-клавиатуры используется стандартная компьютерная клавиатура (USB)**, а архитектура ввода строится по принципу аппаратной модульности (аналог интерфейсов и полиморфизма в ООП).

---

## 1. Почему обычная клавиатура — это огромная победа

На плате **Digilent Nexys A7-100T** порт USB-A (J5) подключен к встроенному микроконтроллеру **Microchip PIC24**.
1. **Заводская прошивка PIC24 спроектирована именно для стандартных клавиатур:**
   * Вы вставляете обычную USB-клавиатуру в порт J5.
   * PIC24 опрашивает ее по USB HID и аппаратно транслирует нажатия клавиш в стандартный двухпроводной протокол **PS/2** прямо на ножки FPGA:
     * **`PS2_CLK`** — пин **`F4`** (стандарт `LVCMOS33`)
     * **`PS2_DATA`** — пин **`B2`** (стандарт `LVCMOS33`)
2. **Никаких проблем с USB-стеками:**
   * Нам больше не нужны сложные USB-хосты, конвертеры или внешние программаторы!
   * FPGA получает простой и надежный последовательный поток скан-кодов (Scan Code Set 2).

---

## 2. Как клавиши обычной клавиатуры превращаются в ноты (Раскладка)

Подобно тому, как сделано в музыкальных программах (Ableton Live, FL Studio, GarageBand), два ряда клавиш обычной клавиатуры превращаются в клавиатуру пианино:

```
 Черные клавиши:       W   E       T   Y   U       O   P
                     [C#][D#]    [F#][G#][A#]    [C#][D#]
 Белые клавиши:     A   S   D   F   G   H   J   K   L   ;
                   [ C ][ D ][ E ][ F ][ G ][ A ][ B ][ C ][ D ][ E ]
```

* Нажатие клавиши `A` $\rightarrow$ Скан-код `0x1C` $\rightarrow$ Нота C4 (MIDI 60, До).
* Нажатие клавиши `W` $\rightarrow$ Скан-код `0x1D` $\rightarrow$ Нота C#4 (MIDI 61, До-диез).
* Клавиши `Z` / `X` $\rightarrow$ Переключение октавы вниз / вверх.
* Клавиши `+` / `-` $\rightarrow$ Громкость больше / меньше.
* Клавиша `Space` (Пробел) $\rightarrow$ Смена формы волны (Синус $\rightarrow$ Пила $\rightarrow$ Треугольник $\rightarrow$ Квадрат).

## 3. Модульность в SystemVerilog (Аналог ООП в железе)

В synthesizable SystemVerilog (который идет в прошивку ПЛИС) нельзя динамически создавать классы через `new` или использовать `virtual methods` во время работы, потому что в кремнии нет кучи (heap) и оперативной памяти для vtable.

**Но в SystemVerilog есть аппаратные паттерны, дающие ровно такой же результат:**

### Архитектурный паттерн: "Каноническая шина событий" (Hardware Strategy Pattern)

```
  [ Драйвер PS/2 Клавиатуры ] ──┐
                                ├─► [ Канонический интерфейс NoteEvent ] ──► [ Звуковой движок ]
  [ Драйвер MIDI (UART)     ] ──┤                                       └──► [ Визуализатор VGA ]
                                │
  [ Драйвер кнопок платы    ] ──┘
```

1. **Единый контракт (Интерфейс):**
   Все источники ввода обязаны приводить свои данные к одной и той же структуре:
   * `event_valid` (1 такт: произошло событие)
   * `event_down` (1 = клавиша нажата, 0 = отпущена)
   * `event_note[6:0]` (универсальный номер ноты 0..127)
   * `event_velocity[6:0]` (громкость / сила нажатия)

2. **Полная развязка:**
   * Звуковой синтезатор и Визуализатор экрана **ничего не знают** о том, откуда пришла нота — с обычной клавиатуры, с кнопок платы или из UART.
   * Они подписаны только на канонический `NoteEvent`.
