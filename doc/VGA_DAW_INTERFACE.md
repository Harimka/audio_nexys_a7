# VGA workstation UI: complete feature record

Дата фиксации: 2026-10-24. Этот документ сохраняет требования, компоновку, состояния, источники данных, реальные назначения управления и ограничения разработанного интерфейса для Nexys A7.

## 1. Статус по веткам

- В `release` на момент этой записи остаётся исходный статический VGA 800×600. Этот документ фиксирует спецификацию интерфейса и результат отдельной разработки; он сам по себе не добавляет VGA-функции в RTL ветки `release`.
- Интерфейсная RTL-реализация была подготовлена в рабочем feature checkout как `src/rtl/vga_daw_ui.sv`, вместе с `src/rtl/waveform_lookup.sv` и подключением состояния в `src/top/audio_nexys_a7.sv`. Для построения piano-roll добавлен экспорт preview-нот из `src/rtl/melody_recorder.sv`.
- Для этой реализации прошла элаборация Icarus. Vivado synthesis/implementation, timing/CDC reports, проверка на Nexys A7 и реальном VGA-мониторе не выполнялись. Нельзя считать дизайн проверенным на плате до этих шагов.
- Исторический источник исходных требований — переданный пользователем `промпт.txt`. Он является входным дизайнерским заданием, а не доказательством реализованного поведения.

## 2. Цели и ограничения

Интерфейс предназначен для автономного музыкального инструмента на Nexys A7: клавиши/транспорт управляют RTL на FPGA, VGA визуализирует состояние платы, звук выходит через её mono audio output. Ноутбук нужен для разработки и прошивки, не как часть игрового тракта.

Ограничения проекта, которые сохраняются и для UI:

- целевой FPGA: `xc7a100tcsg324-1`, top `audio_nexys_a7`;
- только SystemVerilog/обычная логика и уже разрешённые IP; MicroBlaze и Block Design запрещены;
- использовать существующие 800×600 VGA timing, штатный `font_rom.sv` и уже существующий `display_ctrl`; не переносить режим 640×480 из методички;
- не объявлять UI подключённым или проверенным на плате до Vivado и стендовой проверки;
- между аудио- и pixel-доменами передавать цельный снимок состояния, не синхронизировать каждый бит шины отдельной парой триггеров.

## 3. Экран и визуальный стиль

| Параметр | Значение |
|---|---|
| Активное разрешение | 800×600 |
| Частота кадров | цель — 60 Гц (требует проверки по фактическому clock wizard/timing) |
| Цветовой тракт | RGB444, 4 бита на канал |
| Основной фон | `FEA` — тёплый светлый тон |
| Текст, рамки, сетка | `111` — почти чёрный |
| Выделение/форма/активная нота | `06F` — синий |
| Запись/транспортный акцент | `F33` — красный |
| Шрифт | штатный `font_rom.sv`, 8×8; UI масштабирует его для подписей и ноты |

Идея — минималистичная рабочая станция в ретро-стиле: тонкие рамки, простой piano-roll, один график формы сигнала, без фотографий, градиентов, дополнительных font ROM или новых Vivado IP.

### Геометрия интерфейсной RTL-версии

Координаты указаны как активные VGA-пиксели, начало `(0,0)` — левый верхний угол:

| Область | Координаты/размер |
|---|---|
| Заголовок | `y=0..39` |
| Левая клавиатурная шкала | `x=0..59`, `y=92..539`; 28 строк по 16 px |
| Piano-roll | `x=60..539`, `y=92..539`; 16 столбцов по 30 px, шаг сетки 16×30 px |
| Правая колонка | `x=550..798`, `y=42..559` |
| Waveform plot | примерно `x=562..787`, `y=104..257`, горизонтальная ось около `y=174` |
| Active note | примерно `x=600..663`, `y=340..371` |
| Четыре строки треков | `x=562..721`, `y=460..535`, шаг 20 px |
| Volume bar | `x=612..791`, `y=540..555`, 16 ступеней |
| Подсказки команд | `x=16..783`, `y=575..582` |

Эта таблица описывает компоновку конкретной RTL-версии, а не все пиксельные границы рамок/шрифта; любое изменение следует синхронно отразить в коде и этом документе.

## 4. Области интерфейса и поведение

1. **Верхняя строка состояния.** Название устройства, индикатор `REC` с мигающим красным маркером во время записи, и общее состояние `IDLE`, `LIVE` или `PLAY`.
2. **Левая область — piano-roll.** Диапазон четырёх октав C1–B4, ноты C–B, деление по полутонам не заявляется: проектный ввод здесь диатонический C–D–E–F–G–A–B. Метки слева показывают букву ноты и номер октавы. Каждая ячейка содержит позицию события; ноты выбранной дорожки подсвечиваются синим.
3. **Правая верхняя область — waveform.** Отображаются подпись текущей формы и её один цикл: sine, triangle, square или saw. Это графическое превью алгоритма wavetable, не осциллограмма физического аудиовыхода и не измерение PWM/напряжения.
4. **Активная нота.** Крупно выводится последняя активная клавиатурная нота с октавой (например, `C3`). Если удерживаемых нот нет — пустое состояние `--`. При аккорде выводится последняя активированная нота; UI не пытается уместить все голоса в одно поле.
5. **Список дорожек.** Четыре строки показывают номер дорожки, количество записанных событий и отдельные статусы записи/воспроизведения. Выбранная строка выделяется синим.
6. **Громкость.** Полоса из 16 шагов отражает цифровой регистр `volume[3:0]`. Это положение цифрового регулятора, а не измеритель аналоговой амплитуды или loudness.
7. **Нижняя строка управления.** Кратко напоминает клавиатурные команды: F9/Space — запись; Enter — воспроизведение; Esc — стоп; Tab/F10 — следующая дорожка; Backspace — предыдущая; стрелки — форма волны.

### Piano-roll: точный объём preview

Экран показывает только первые 16 событий Note On выбранной дорожки, в порядке записи. Для каждой ячейки в preview сохраняются код ноты и октавы. Индекс высоты вычисляется как `octave * 7 + note_index`; preview раскладывает его по 28 строкам диапазона C1–B4. Текущая схема имеет четыре дорожки и recorder глубиной до 64 событий на дорожку; счётчик в UI показывается в hex-формате. Глубина относится к event recorder, не к количеству PCM samples или секунд аудиофайла.

Recorder может содержать больше событий, но графический preview ограничен 16 Note On. В текущем UI не выведены временные метки событий, Note Off, длительности нот, паузы, темп, точный playhead и история всей дорожки. Поэтому этот экран показывает высоты первых нот, а не полноценное редактирование/временную сетку DAW.

## 5. Данные и интерфейс модулей

Целевой модуль рендеринга: `vga_daw_ui.sv`. Предполагаемые/используемые входы pixel-домена:

| Данные | Источник состояния | Представление |
|---|---|---|
| Выбранная форма 2 бита | глобальный `waveform_select` | название и один период waveform preview |
| Выбранная дорожка 2 бита | регистр выбранной дорожки | выделение строки, preview и счётчик |
| Громкость 4 бита | цифровой `volume` | 16-уровневая полоса |
| Live/Play | состояние аудио и транспорта | верхняя строка состояния |
| `recording[3:0]`, `playing[3:0]` | четыре recorder/sequencer | REC/PLAY статусы строк |
| `event_counts[27:0]` | четыре счётчика по 7 бит | количество событий каждой дорожки |
| `preview_counts[19:0]` | четыре счётчика по 5 бит | число доступных ячеек piano-roll, максимум 16 |
| `preview_notes[319:0]` | первые 16 pitch-кодов каждой дорожки | высота в piano-roll |
| active note, octave, valid | note stack/клавиатурный путь | крупная активная нота |
| `h_coord`, `v_coord` | существующий `display_ctrl` | пиксельная адресация 800×600 |

Рендеринг формирует отдельные 4-битные каналы `red`, `green`, `blue`; внешняя обвязка должна учитывать `disp_enbl` и синхронизацию существующего VGA-конвейера.

### Тактовые домены

Состояние нот/дорожек/звука находится в аудиодомене, а пиксели формируются в `pixel_clk`. Для реализации использовался bundled-data snapshot: источник фиксирует весь многобитный payload, затем меняет toggle; toggle проходит двухтриггерную синхронизацию, и при обнаружении изменения принимается согласованный payload. Источник держит payload стабильным между обновлениями. Подход допустим лишь при соблюдении setup/hold-предпосылки протокола и частоте событий существенно ниже скорости pixel-домена; для синтезированной схемы требуется проверить CDC report и RTL timing. При частых/потоковых событиях нужен handshake с подтверждением или асинхронный FIFO.

## 6. Управление: требование макета и фактический RTL

В переданном дизайнерском prompt были предложены `BTNU=REC`, `BTNC=play/pause`, `SW[4:3]=wave`, `SW[2:0]=octave`; также упоминался MIDI UART RX на C4. Это идеи макета, а не доказанные команды текущего release RTL.

Для интерфейсного feature RTL фактические привязки клавиатуры заданы существующим PS/2 decoder и транспортом:

| Команда | Действие |
|---|---|
| F9 или Space | начать/остановить запись выбранной дорожки |
| Enter | начать playback выбранной дорожки |
| Escape | остановить playback |
| Tab или F10 | выбрать следующую дорожку |
| Backspace | выбрать предыдущую дорожку |
| Стрелки | циклически выбрать sine → triangle → square → saw |

На самой плате release RTL сохраняет назначения демо: BTNC — demo play/pause, BTNL/BTNR — изменение demo-ноты, BTNU/BTND — громкость, `SW[2:0]` — октава demo-tone. Поэтому надписи интерфейса должны соответствовать реально интегрированной ветке, а не просто повторять пожелание из prompt.

Клавиатурные ряды задают ноты и октавы отдельно: `1..7` = C1–B1, `Q..U` = C2–B2, `A..J` = C3–B3, `Z..M` = C4–B4. Клавиши вне этих первых семи позиций ряда не становятся дополнительными нотами в этом mapping.

## 7. Что не входит в обещания экрана

- VGA не декодирует USB MIDI и не показывает состояние устройства на USB.
- Waveform preview не является реальным аудио sample buffer/spectrum analyzer; FFT/фильтры не реализованы этим UI.
- Значок REC и счётчик не означают запись файла WAV/MP3 на microSD. Track recorder в рассмотренной feature-архитектуре хранит события нот в памяти FPGA.
- Preview не отражает длительность, velocity, частоту/громкость по времени, sustain-pedal или playhead.
- `LIVE` означает наличие состояния генерации звука согласно RTL, а не гарантированную слышимость в наушниках.
- Целевой экран не является интерактивной мышью/GUI; команды поступают от физической клавиатуры и текущего transport decoder.

## 8. План переноса реализации в release

1. Перенести UI RTL и подходящие waveform/preview-модули поверх release с адаптацией к реальным интерфейсам этой ветки; не переносить случайно SD/WAV модули.
2. Проверить модули по Tcl-рекурсивному включению `src/rtl/*.sv` и отдельную top-level элаборацию.
3. Запустить Vivado Synthesis/Implementation; устранить синтезные ошибки, изучить utilization, timing, unconstrained paths и CDC.
4. Исправить/проверить VGA pixel pipeline alignment: RGB, DE, HS, VS; проверить 800×600 timing и реальный монитор через фактически имеющийся VGA-адаптер.
5. На плате последовательно проверить заставку/текст, активную ноту, смену формы, четыре строки треков, preview 1/16 нот, REC/play status и громкость.
6. Снять наблюдаемые результаты и обновить этот документ/README; до этого статусы считать «RTL разработан, плата не проверена».
