# Roadmap: MicroLab → FPGA wavetable → наушники

Цель: прямое управление звуком на Nexys A7-100T с Arturia MicroLab mk3; наушники подключены к плате, ноутбук в конечной схеме только прошивает. Детальный контекст и оговорки — [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md). Срок и подробные критерии хакатона неизвестны; этапы ниже не являются обещанием сроков или баллов.

## Этап 0. Сохранить исходную рабочую точку — выполнено частично

Сохранены baseline README/manifest, исходники, журнал `Programmed`, Git-история, ограничения и документы для агентов. Сформированы производные архивы исходников; оригинальный ZIP не переписан. Воспроизводимая сборка новой MIDI-версии в Vivado и её bitstream пока отсутствуют.

Критерий закрытия: на доступном Vivado воспроизвести baseline, записать версию tools/part/top и проверенный commit. Сгенерированные bitstreams не коммитить по AGENTS.md; при необходимости сохранить отдельно с hash и происхождением.

## Этап 1. Установить реальный вход от MicroLab — главный открытый этап

Сделано: MicroLab определяется в Linux (`1c75:020c`), MIDI-порт `20:0`, реальные Note On/Off/CC/Pitch Bend получены. Декодер payload в RTL этого этапа физически не заменяет.

Дальше:

1. Получить полный USB descriptor dump MicroLab, установить все интерфейсы, наличие/отсутствие Boot HID, MIDI revision, endpoints и cable mapping. Опубликовать только очищенные технические данные.
2. Сопоставить экземпляр Nexys с reference schematic; выяснить по доступным материалам организаторов, нет ли специальной PIC24 firmware/предусмотренного способа подключения. Пользователь версии firmware не знает; не перекладывать это выяснение на него повторным вопросом.
3. Проверить наблюдаемый выход PIC24 при MicroLab доступным разрешённым способом. Не добавлять ILA, не модифицировать PIC24 без плана восстановления. Если нужных tools/измерений нет, точно записать чего не хватает.
4. По результатам выбрать транспорт:
   - Если готовый поток нот/команд уже выходит с PIC24 — описать измеренный формат и сделать адаптер в FPGA.
   - Если подтверждена стандартная HID-only firmware — оценить отдельную PIC24 USB-MIDI firmware (host enumeration, descriptors, bulk IN, disconnect, передача в FPGA, programmer/recovery). На текущем комплекте programmer/готовая firmware не подтверждены.
   - Внешний host — альтернативная ветка, требующая нового оборудования и проверки электрических уровней/совместимости.
   - Ноутбук USB-MIDI→UART — только диагностический обход или отдельно согласованный иной финальный вариант; не считать его выполнением прямого подключения.

Критерий закрытия: реальное нажатие/отпускание MicroLab наблюдается на входе FPGA; известны физическая схема, протокол, clock/reset, pinout, скорость и поведение при отключении. Если такой путь на доступном комплекте не подтверждается, сообщить условный аппаратный блокер и доказательства, не обещать универсальное решение одним RTL.

## Этап 2. Преобразовать команды в состояние ноты — реализовано и проверено симуляцией

Есть byte-stream MIDI decoder, USB-MIDI 1.0 payload decoder, note state, UART wrapper. Поддержаны Note On/Off, velocity=0, канал, running status для byte stream, фильтрация неподдерживаемых событий, пакетные ошибки/backpressure. Нет USB host в этих модулях.

Дальше: адаптировать выбранный на этапе 1 транспорт. Зафиксировать channel/cable policy, сброс и очистку голоса при disconnect, границы буферов и переполнение. Добавить тесты только под фактический формат входа.

Критерий закрытия: реальные команды попадают в числовые поля FPGA; чужой канал/ошибочные данные не выключают чужую ноту; нет зависшего голоса после disconnect/reset. Для нескольких одновременных клавиш чётко показать текущую mono-policy.

## Этап 3. Таблично-волновой синтез — минимальное ядро реализовано

Есть 256-точечный sine wavetable, фаза 32 bit, таблица 128 MIDI-нот, velocity→амплитуда; один голос. Интеграционный payload→voice тест проверяет около 440 Гц для A4 и поведение ready/reset/Note Off.

Последующие улучшения после рабочего минимального тракта:

1. Выбрать нужные тембры/таблицы; воспроизводимо генерировать коэффициенты, учитывать лицензии сэмплов.
2. Добавить короткую attack/release огибающую против щелчков, если время позволяет; затем ADSR по выбранному объёму.
3. Масштабировать громкость относительно нуля signed PCM, затем преобразовывать в unsigned PWM; не усиливать DC-смещение. Проверить saturation и отсутствие переполнения.
4. Если нужно — несколько голосов, allocation/stealing, расширенная сумма и headroom; пока полифония не является подтверждённым обязательным критерием.
5. Sustain/CC1/Pitch Bend — будущие опции: MicroLab их передаёт, текущая версия их не использует. Для каждой функции определить диапазон и проверки.

Критерий закрытия минимального этапа: частоты/амплитуда/тишина соответствуют командам; частота зависит от реального темпа принятых сэмплов, не от количества циклов симуляции; backpressure не теряет/не дублирует сэмплы.

## Этап 4. Интеграция с аудиовыходом и Vivado — не выполнено для MIDI-версии

Сохранить FIFO/PWM и аппаратный AUD_PWM 0/Z. Проверить latency ROM/BRAM, valid/ready, reset и CDC; синхронизировать переключатели при необходимости. Сначала использовать один источник нот, затем управление выбором источника/громкостью.

Собрать на Vivado для `xc7a100tcsg324-1`, без MicroBlaze/Block Design и запрещённых IP. Проверить DRC, timing, ресурсы, CDC и реальные частоты. Сгенерировать и загрузить именно MIDI bitstream; записать commit/hash и результаты.

Критерий закрытия: подтверждён слышимый звук в MONO AUDIO OUT при реальных командах, ноты меняются правильно, release/reset выключает звук, нет зависаний. В отчёте разделить эксперимент с ноутбуком и автономный вариант. Локальный Icarus и старый `Programmed` этот этап не закрывают.

## Этап 5. Надёжность основы — известные незакрытые дефекты

Исправить reset при потере PLL lock и VGA VS по регрессионным тестам правильного поведения. Текущий baseline намеренно воспроизводит дефекты; не просто переименовать его PASS. Проверить повторный reset, пустой/полный FIFO, остановку/возобновление, быстрые ноты, смену источника, disconnect/reconnect. Осознанно исправлять выявленный дефект, не расширять задачу до полного переписывания baseline.

Критерий закрытия: тесты фиксируют правильное поведение, ручные проверки воспроизводимы; ресурсные/timing изменения задокументированы.

## Этап 6. VGA и периферия — UI реализован, интеграция требует Vivado/стенд

Добавлен `vga_daw_ui.sv`: 800×600 RGB444, выбранная дорожка с 16-шаговым нотным piano-roll, статусы/счётчики четырёх дорожек, активная нота, селектор формы/preview и цифровая громкость. Recorder вычисляет отдельную матрицу длительностей/пауз/аккордов после REC; playback не квантуется. Матрица публикуется единым аудио→pixel snapshot; документация и ограничения — `UI_FEATURE_MAP.md`.

Интерфейсные `SW[4:3]`/`BTNU REC` из эскиза не подключены: отображаются фактические назначения текущего RTL (стрелки формы, F9/Space запись, Enter/Escape playback, F10/Tab и Backspace дорожки). Интерфейс не показывает точный временной playhead, аналоговый уровень, PCM или USB connection status; окно нот ограничено 16 фиксированными шагами и 28 клавишными высотами.

Следующий шаг: синтезировать именно эту ветку в Vivado, проверить timing/resource/CDC отчёты, затем увидеть её на мониторе. Ни интерфейс, ни синхронизация состояния для VGA ещё не прошли эту проверку на стенде.

## Этап 7. Автономная демонстрация и защита — не выполнено

Проверить целевой тракт без участия ноутбука в передаче нот; отдельно обеспечить питание платы/MicroLab. Игра, повторные нажатия, отпускание, разные velocity, повторное включение, reset, длительная работа и отключение клавиатуры. Для моно-версии явно объяснить ограничение одного голоса.

Подготовить инструкцию подключения/запуска, схему блоков, протокол с примером реальной ноты, объяснение wavetable/фазы/частоты/PCM/PWM, таблицу своего вклада/заимствований, лицензии и источники. Подготовить раскрытие использования кода и ИИ для эксперта и презентации; не отправлять ничего третьим лицам без поручения.

Критерий закрытия: другой участник запускает проверенную версию по инструкции, команда объясняет устройство и ограничения. Презентация и видео/измерения подтверждают именно реализованный путь. Статусы: «сделано», «симуляция», «на плате», «предложение» не смешивать.

## Вне текущего обязательного объёма

SD/FAT/WAV/MP3/DDR2/процессор/FFT не реализованы и не являются автоматически обязательными. Добавлять их только после получения критериев или выбора команды. Предварительно сконвертированный MP3 не называть аппаратным MP3 decoder. Нельзя обещать, что текущий интерактивный синтезатор уже удовлетворяет всем требованиям исходного «плеера».

## Роли для следующей команды агентов

При явно запущенной многoагентной работе: интегратор владеет top/XDC/Tcl/контрактами; исследователь транспорта — descriptors/PIC24/физическое соединение; звук — voice/таблицы/огибающая; верификация — протокол/поток/reset/стенд; VGA — UI после стабилизации контракта. Не поручать реализацию USB host и физическое измерение агенту, у которого нет соответствующих интерфейсов/tools, и не принимать текстовый план за готовый host.

Сначала закрыть неизвестный вход и минимальный аудиотракт. Не распараллеливать предположения о разных несовместимых транспортных схемах в общий top.

## Дополнение: ветка `future` от `release`

Ветка `future` добавляет к `release` восьмиголосный клавиатурный синтез и запись временной последовательности Note On/Off событий. `F9` переключает запись, `Enter` запускает сохранённый фрагмент, `Escape` останавливает его. Буфер вмещает 64 перехода (примерно 32 полные ноты), volatile и хранит только события с относительным временем; WAV/MP3/SD не реализованы. Unit/regression и top elaboration прошли Icarus; синтез Vivado и проверка на стенде остаются следующими шагами. Подробности — [MUSIC_RECORDING.md](MUSIC_RECORDING.md).
