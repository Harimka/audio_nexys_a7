## Приоритетная задача сейчас

Обязательно поддержать цифры 6, 9 и 0. Остальные разряды должны быть погашены. Звуковой тракт на этом шаге не входит в критерий.

Это **симуляция RTL**, а не доказательство Vivado-сборки или поведения физической клавиатуры.

Архив текущего состояния создан локально: `audio_nexys_a7_keyboard_digits.zip` в каталоге выше `outputs/` (в рабочем окружении: `/Users/danilataborov/Documents/Codex/2026-10-24/new-chat/audio_nexys_a7_keyboard_digits.zip`). ## Цель проекта и постановка

- Исходный проект — демо цифрового звука для Artix-7 на Nexys A7-100T. Пользователь хочет довести его для хакатона, ключевая технология — таблично-волновой синтез, обработка и генерация звука в FPGA.
- Итоговое направление, ранее проговорённое: клавишный ввод → распознавание ноты → wavetable на FPGA → MONO AUDIO OUT → наушники; ноутбук нужен для разработки/прошивки, не для игрового ввода.
- В промежуточной ветке пользователь отказался от MicroLab и выбрал обычную USB-клавиатуру, подключённую к USB HOST платы. Каждой клавише предполагается назначить ноту и октаву. После проверки цифр следующий шаг — определить реальные scan codes, назначить ноты/октавы, затем связать ввод с существующим wavetable и проверить note-on/note-off и слышимый звук.
- Пользователь уточнил, что цифры должны быть именно отображены на плате, сначала в одном окне/разряде из восьми; впоследствии отдельно настоял на 6, 9, 0.
- Эта временная задача не заменяет и не переписывает без команды итоговые цели хакатона. Обязательность SD/WAV/MP3 и полный критерий неизвестны.

### 2. Первоначальный путь с MicroLab и его статус

- Сначала обсуждался Arturia MicroLab mk3 как MIDI-клавиатура; пользователь подтвердил USB-соединение фотографией с Linux `lsusb`: `1c75:020c Arturia MicroLab mk3`. На фото `aseqdump -l` показал MIDI port `20:0`; далее видны Note On/Off и pitch values (например 48, 50, 52, 53, 55), velocity, CC1 и Pitch Bend.
- Это подтверждает MicroLab → Linux ALSA MIDI в конкретной проверке; не подтверждает MicroLab → FPGA, полный USB descriptor set или звук через плату.
- Пользователь не имеет отдельного USB-MIDI host/модуля или PICkit; есть плата, MicroLab и USB-кабели. MicroLab подключался к USB HOST J5, наушники — к MONO AUDIO OUT. Пользователь хотел ноутбук только для прошивки.
- Reference Manual Nexys A7, показанный пользователем (секция USB HID Host, стр. 14/33), говорит: PIC24FJ128 auxiliary MCU даёт USB embedded HID host; может работать с одной Boot HID мышью или клавиатурой; hub support отсутствует; PIC24 преобразует keyboard/mouse к PS/2 для FPGA. Иные линии связаны с конфигурационным интерфейсом FPGA.
- **Потенциальное ограничение, не измеренный факт:** стандартная документация предполагает HID→PS/2, не USB-MIDI. Не установлено, какая PIC24 firmware реально загружена на учебную плату, есть ли переделка/особая firmware или дополнительные USB interfaces у MicroLab. В ZIP PIC24 firmware не найдено, но это не доказывает отсутствие firmware в самой плате или у организаторов. Не заявлять категорично, что прямой MicroLab невозможен на конкретной плате; но и не обещать, что RTL декодер устраняет USB host/физическую границу.
- Пользователь затем решил **полностью исключить синтезатор из текущей работы**: выбран обычный USB-клавиатурный ввод. MicroLab и его MIDI факты остаются историческим/будущим контекстом, не текущим заданием.

### 3. Прошивка и ранняя отладка

- Пользователь спрашивал, как собирать битстрим, что такое bitstream, как прошивать плату и что значит Vivado сообщение. Bitstream — конфигурационный файл FPGA, не исходник и не прошивка PIC24.
- На фото Vivado Hardware Manager видел `xc7a100t_0`, статус `Programmed`; Tcl сообщал `Device ... is programmed with a design that has no supported debug core(s) in it`. Это информационное отсутствие ILA/debug cores, не ошибка программирования. Не доказывает звук/работоспособность логики.
- На фото индикатора с `OFF` пользователь затем сообщил, что цифры `1234567` выводились, а при тесте ввода были нули/ничего. Это относилось к старому загруженному проекту, не к текущему новому RTL. Не выдавать это за проверку текущей реализации.
- Питание платы, USB PROG/UART и USB HOST — разные функции/разъёмы. Для JTAG bitstream используется PROG UART/USB-JTAG; USB HOST принимает периферию. После обычного программирования bitstream находится в volatile FPGA config SRAM и теряется после power cycle.
- Ранее была дана неточная инструкция будто в ZIP уже есть `.xpr`. Фактически архив проекта не включает сгенерированный каталог `vivado/`; корректная процедура: распаковать ZIP → терминал в корне `audio_nexys_a7`, где лежит Makefile → `make deploy` (при установленном Vivado; генерирует проект и запускает GUI) → `Generate Bitstream` → Hardware Manager / Auto Connect / Program Device. `make deploy` сам по себе не запускает синтез/реализацию/прошивку. Этот порядок также внесён в `BOARD_BRINGUP.md`.

## Состояние кода и проверки

- Базовый проект включает DDS, FIFO, PWM mono audio, статический VGA, кнопки/переключатели, семисегментный индикатор и Clocking Wizard.
- В истории добавлялись MIDI UART decoder/state, 256-точечный wavetable и экспериментальный USB-MIDI payload decoder/voice. Они не являются интегрированным прямым MIDI host для J5. Ноутбучный MIDI→UART bridge является диагностическим экспериментом и противоречит автономной игровой цели; не предлагать как конечное решение.
- Текущий реализованный шаг: PS/2 decoder для цифр 0–9 и seven segment one-digit mask. `python3 tests/audit/run_audit.py .` и `git diff --check` прошли; пользователь подтвердил работу на физической плате. Симуляция тестирует digits/top+keypad, release/extended filtering и маску `AN[0]`. Аудио не входит в этот этап.
- Vivado и физическая Nexys A7 недоступны помощнику в его macOS окружении; пользователь запускает Linux/Vivado 2024.1. Не утверждать, что текущие источники уже собраны/загружены.
- Известные baseline дефекты из тестового аудита: повторный reset при потере PLL lock и сдвиг VS VGA. Зелёный baseline audit может проверять воспроизведение дефекта, не исправление.
