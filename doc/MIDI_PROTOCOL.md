# MIDI-команды → числа → звук FPGA

## Что подтверждено на стенде

Фото пользователя от 2026-10-24: `lsusb` определил `1c75:020c Arturia MicroLab mk3`; `aseqdump -l` показал вход `20:0 MicroLab mk3`. Затем `aseqdump -p 20:0` показал Note On/Off на канале 0 для нот 48, 50, 52, 53, 55, Pitch Bend и CC1. Это подтверждает MicroLab → Linux по USB-MIDI. Передачу в FPGA и звук новая проверка не подтверждает. Фотографии и регистрационные данные не публикуются.

Наблюдавшиеся Note On/Off соответствуют, например:

| Событие | MIDI-байты, hex | Поля декодера |
|---|---|---|
| Нажатие ноты 48, velocity 36 | `90 30 24` | on=1, channel=0, note=48, velocity=36 |
| Отпускание ноты 48, release velocity 57 | `80 30 39` | on=0, channel=0, note=48, velocity=57 |
| Нажатие A4, velocity 100 (тестовый пример) | `90 45 64` | on=1, channel=0, note=69, velocity=100 |
| Выключение A4 через Note On velocity=0 | `90 45 00` | on=0, channel=0, note=69, velocity=0 |

Номер ноты уже передаётся клавиатурой, назначать диапазоны USB-значений вручную не требуется. Частота: `f = 440 × 2^((note − 69)/12)` Гц. У ноты 48 частота около 130,81 Гц; MIDI-номер однозначен независимо от разного обозначения октав в программах.

## Реализованные границы модулей

Все перечисленные интерфейсы синхронны одному `clk`, reset `rst_n` активен низким уровнем и асинхронно устанавливается. При входе из другого домена нужен FIFO/handshake; соединение многобитных шин напрямую между разными clk недопустимо.

- `midi_note_decoder.sv`: вход `byte_data[7:0]` + строб `byte_valid`; выходные числовые поля `event_on`, `event_channel[3:0]` (канал 0…15), `event_note[6:0]`, `event_velocity[6:0]` и однотактный `event_valid`. Note On/Off, running status и real-time байты между частями сообщения поддерживаются. Другие статусы отменяют сборку незавершённой ноты; их данные не превращаются в ноты. SysEx, CC, Pitch Bend, sustain и System Reset не реализованы как команды управления синтезатором. Потребитель событий обязан принимать каждый строб; интерфейс без backpressure. Поля выставляются на фронте, принимающем velocity.
- `usb_midi_note_decoder.sv`: получает **уже извлечённый USB host-ом** 32-битный USB-MIDI 1.0 Event Packet. `packet_data[7:0]` — первый USB-байт, далее `[15:8]`, `[23:16]`, `[31:24]`. Note On A4, velocity=100: USB-байты `09 90 45 64`, значение шины `32'h64459009`. На входе `packet_valid && packet_ready`, на выходе `event_valid && event_ready`; один буфер события, поля удерживаются при остановке, возможна передача каждый такт. Поддерживаются CIN=8/9 на выбранном `CABLE_NUMBER` (по умолчанию 0). Note On velocity=0 трактуется как Note Off. Несогласованные CIN/status и несемибитные note/velocity дают однотактный `packet_error` без события. Другие CIN и виртуальные кабели пропускаются; CIN=F с произвольным потоком байтов не поддерживается. Это не USB enumeration, USB PHY или MIDI 2.0 UMP.
- `midi_note_state.sv`: однотактные события → `gate`, `channel`, `note`, `velocity`. Последнее нажатие заменяет голос; отпускание выключает только совпавшие ноту **и канал**. Release velocity не включает звук. Возврата к более ранним удерживаемым клавишам нет. Полифонии пока нет. Состояние обновляется на следующем фронте после выдачи события декодером.
- `midi_uart_receiver.sv`: существующая UART-обёртка теперь использует общий byte decoder и note state. Исправлено прежнее выключение голоса отпусканием такой же ноты с другого канала. Порты top не изменены; C4 по-прежнему относится только к PROG/UART, не J5 USB HOST.
- `usb_midi_voice.sv`: интеграционный модуль payload decoder → note state → `midi_wavetable.sv`. Выдаёт unsigned PCM 16 bit (тишина 32768). Осциллятор продвигается на `sample_ready`; частоты таблицы рассчитаны на `49158650/1024 ≈ 48006,49` принятых сэмплов/с. Стабильный голос удерживает сэмпл при `sample_ready=0`; изменение gate/note/velocity может изменить выход и при остановке. При отключении/повторном перечислении USB host обязан сбросить эту цепочку через `rst_n`, чтобы очистить отложенное событие и голос.

Новых Vivado IP, CPU, Block Design и изменений MMCM нет. `usb_midi_voice` пока не подключён к board top: физического источника USB-payload в имеющемся проекте нет. Существующий аудиовыход top сохраняет PWM 0/Z.

## Где выполняется мост

```text
Прямая целевая схема:
MicroLab --USB--> [USB-MIDI host] --payload/числа--> FPGA decoder
                                                    ↓
                                              wavetable → PWM → наушники
```

Код приёма USB должен исполняться на устройстве, физически имеющем доступ к USB-шине. У Nexys A7 J5 это PIC24. Для прямого кабеля MicroLab → J5 нужна отдельная firmware PIC24 с USB-MIDI host и передача событий в FPGA через доступные линии; существующая HID→PS/2 firmware эту функцию не выполняет. Обычная FPGA-прошивка не меняет программу PIC24. Программатор и процедура восстановления отсутствуют в подтверждённом комплекте. Подробнее: [DIRECT_USB_MIDI.md](DIRECT_USB_MIDI.md).

Стандовый путь через ноутбук уже имеет программный мост `tools/midi_uart_bridge.py`: он пересылает только Note On/Off в UART 115200 8-N-1. Ноутбук не синтезирует звук. Этот путь требует ноутбука во время игры и не выполняет ранее заданное требование прямого подключения. Наличие успешного `aseqdump` не доказывает прямую работу с J5. Автономный вариант требует изменения PIC24 или внешнего host; одним декодером нот его не заменить.

## Проверки

```bash
python3 tests/audit/run_audit.py .
```

Icarus: UART Note On/Off; наблюдавшиеся ноты MicroLab с ненулевой release velocity; настоящий running status с пропущенным status byte; real-time в середине сообщения; отмена состояния через CC/SysEx; совпадение каналов; USB packing; удержание события при backpressure; ошибочные пакеты; 4096 USB note-событий по всем нотам/каналам; интеграция USB-payload → wavetable; A4 около 440 Гц, диапазон амплитуды при velocity=100, удержание фазы при остановке приёма сэмплов и тишина после отпускания/reset. Board/simulation top и исходный TB элаборируются с port-only clock stub.

Baseline по-прежнему воспроизводит известные дефекты reset/VGA; они не исправлены этим изменением. Vivado здесь отсутствует; синтез, timing, настоящий USB host, PIC24 firmware, аналоговый выход и новая версия на плате не проверены.

## Источники

Формат USB-MIDI Event Packet: [USB-IF Device Class Definition for MIDI Devices 1.0, раздел 4, таблицы 4-1 и 4-2](https://www.usb.org/sites/default/files/midi10.pdf). Нормативная спецификация использована как описание протокола; реализация RTL и тестов написана в проекте, чужие HDL-блоки не заимствованы. Раскрытие использования ИИ и источников — по общим правилам проекта.

[Методичка UART](https://github.com/YuraThomas/Methoda/tree/main/Interfaces/My_UART) содержит UART/FSM материалы и примеры RX/TX; её README на main описывает старую версию статьи. Она полезна для UART-этапа после USB host, но сама не является USB-MIDI host для PIC24.
