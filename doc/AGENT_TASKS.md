# Задачи для команды агентов

План для будущей разработки по запросу пользователя. При четырёх слотах — координатор и до трёх исполнителей. При меньшем числе слотов выполнять последовательно. Перед началом прочитать `AGENTS.md`.

## Координатор/интегратор

Владеет архитектурой, `src/top/audio_nexys_a7.sv`, `src/top/audio_nexys_a7.xdc`, `src/sim/top_audio.sv`, общими Tcl/Makefile и документацией состояния. Уточняет критерии/срок, согласует интерфейсы до параллельных правок, интегрирует и проверяет результаты.

Исполнители не редактируют общие top параллельно: передают контракт и пример подключения. Изменение XCI — отдельное решение с пересчётом частот. Один владелец файла в момент времени; конфликтующие правки согласовывать, не затирать. Сохранять рабочие версии.

## A. Reset, периферия, CDC

**Файлы:** `reset_button_debouncer.sv`, `reset_sync.sv`, `button_debouncer.sv`, `button_ctrl.sv`, `sevseg_ctrl.sv`, новые стабилизация SW/передача состояния по согласованию.

**Работа:** безопасное повторное включение reset при потере lock, сценарий старта/восстановления; стабильные SW; целостные снимки состояния для индикаторов/VGA; clock enable сканирования.

**Приёмка:** reset при старте, кнопке, потере lock; синхронное снятие в каждом домене; нет зависания после восстановления; одно событие на устойчивое нажатие; целостная шина. Для включения reset не требовать работающего выходного клока, который может остановиться.

**Передача:** порты, домены, полярности, задержки, требования к top/XDC и проверки.

## B. Цифровой звук

**Файлы:** `tone_generator.sv`, `pwm.sv`, `fifo.sv`, новые звуковые модули.

**Работа:** sample/valid/ready, латентность памяти, signed PCM/volume/mute, музыкальный источник по критериям; синус/огибающая при необходимости. Не расширять задачу до SD/MP3 без решения интегратора.

**Приёмка:** частоты и длительности по принятым сэмплам; удержание при backpressure; нет потерь/повторов; тишина, края громкости, pause/end; аппаратная обёртка сохраняет AUD_PWM 0/Z.

**Передача:** формат/диапазоны, темп выдачи, очистка/заполнение FIFO, тестовый источник и измерения.

## C. VGA/UI

**Файлы:** `display_ctrl.sv`, `vga_demo.sv`, `font_rom.sv`, новые UI-модули. Логотип менять при необходимости.

**Работа:** исправление VS с учётом pipeline; 800×600 и 1056×628; реальное состояние/время/громкость; простая waveform/уровень. FFT только при требовании.

**Приёмка:** 480000 активных пикселей, правильные front/sync/back интервалы и полярности, согласование RGB/DE/HS/VS, целостный снимок состояния. SDL по координатам не проверяет HS/VS.

**Передача:** контракт снимка, задержки pipeline, проверки развёртки и результат визуальной проверки при доступных инструментах.

## D. Верификация

**Файлы:** `tests/`, `src/tb/tb_audio_nexys_a7.sv`, отчёты. RTL меняет владелец соответствующей задачи.

**Работа:** baseline, регрессионные тесты правильного поведения, ремонт портов/timescale/частоты/завершения штатного TB; проверки контрактов и ошибок.

**Приёмка:** новые тесты исправления ловят дефектный вариант и проходят исправленный; команды воспроизводимы; ожидания следуют требованиям. Отражать ограничения clock stub. При наличии Vivado фиксировать реальные timing/CDC/resources, при отсутствии не объявлять их пройденными.

## E. SD/WAV — после выбора объёма

**Файлы:** новые SD/SPI, block/file reader, WAV parser. Top/XDC изменяет интегратор; общий FIFO не менять параллельно агенту звука.

**Работа:** питание SD_RESET=0 после передачи управления; сектор → файл → RIFF-чанки → PCM → поток; явный поддерживаемый формат; буфер, underrun, ошибки.

**Приёмка:** байты совпадают с эталоном; неизвестные WAV-чанки/нечётные размеры обработаны; EOF/ошибки предсказуемы; непрерывность и запас буфера измерены на карте.

## F. MIDI — после установления входа

**Файлы:** новые приёмник/мост, parser, интерфейс событий; изменения DDS согласовать с агентом звука.

**Работа:** подтвердить путь DIN/USB/ПК; Note On/Off, channel, velocity, полутона; дополнительные сообщения по требованиям.

**Приёмка:** реальный путь событий проверен; Note On velocity=0 выключает ноту; нет зависших нот; участие ПК указано честно. Не обещать USB-MIDI через Boot HID host.

## Если обязателен MP3

Координатор отдельно выбирает разрешённую архитектуру, проверяет лицензию декодера и производительность. CPU/тулчейн/память/шина/декодер меняют весь план. Предобработанный PCM не доказывает декодирование MP3 на устройстве.

## Порядок интеграции

1. Координатор фиксирует baseline и контракты.
2. Первая волна: reset/периферия, VGA, подготовка регрессионных тестов; ожидания согласовать до исправлений.
3. Интеграция основы; затем звуковой тракт и музыкальный источник, UI по общему контракту.
4. SD/WAV, MIDI либо MP3 по подтверждённым требованиям; не все направления сразу.
5. Интеграционные проверки, стенд, документация, репетиция защиты.

Отчёт каждого: проблема → поведение → файлы → команды/факты проверки → риски → следующий шаг интеграции.
