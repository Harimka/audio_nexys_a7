# Музыкальный плеер на Nexys A7-100T

**Промежуточный результат:** базовая USB-клавиатура успешно управляет цифрами 0–9 на одном разряде Nexys A7; остальные разряды погашены. Реализация находится в ветке `feature/keyboard-digit-display` (commit `51b8439`). Краткий контекст, расположение кода и пример mapping — [doc/KEYBOARD_DIGIT_PROGRESS.md](doc/KEYBOARD_DIGIT_PROGRESS.md). Дальше — назначить клавишам ноты/октавы и подключить wavetable; звуковой тракт с клавиатуры пока не подтверждён.

Стартовый проект на SystemVerilog для учебного хакатона: исходное демо организаторов, технический разбор, воспроизводимые проверки и контекст для нескольких ИИ-агентов.

**Сейчас реализованы:** исходный DDS-демосинтезатор, монофонический MIDI Note On/Off приём через UART, табличная синусоида, PWM-аудиовыход, статический VGA 800×600, кнопки и семисегментные индикаторы. Добавлен ноутбучный USB-MIDI → USB-UART мост для Arturia MicroLab mk3. Новый MIDI тракт проверен в Icarus, но ещё не собран Vivado и не прошит на плате; прежний архивный bitstream был загружен успешно. WAV/MP3/SD не реализованы. Пользователь подтвердил: ноутбук используется только для прошивки. Компьютерный мост не выполняет это требование и не является целевым решением. Прямой вход MicroLab через USB HOST пока не реализован; аппаратное ограничение и варианты описаны в [doc/DIRECT_USB_MIDI.md](doc/DIRECT_USB_MIDI.md).


Добавлены общий декодер MIDI → числовые поля, декодер USB-MIDI 1.0 payload и интеграционный модуль payload → wavetable. UART использует общий декодер; USB-payload модуль пока не соединён с J5/board top. [Формат, модули, подтверждённые нажатия MicroLab и результаты тестов](doc/MIDI_PROTOCOL.md).

- MicroBlaze и сборка системы в Vivado Block Design запрещены.
- Из Vivado IP разрешены только Clocking Wizard, Block Memory Generator, Distributed Memory Generator, MIG, AXI XBAR.
- Открытый сторонний код разрешён с учётом лицензий и раскрытием источников эксперту в Telegram и в презентации.
- ИИ разрешён; оценка технических частей зависит от понимания решения командой.
- Максимумы: звук 45, VGA 25, периферия 20, презентация 10. Первые три умножаются на отдельные коэффициенты понимания.

## Запуск

Сохраните имя каталога `audio_nexys_a7`: Tcl определяет имя top по имени папки. Команды запускаются из корня репозитория.

```bash
# Нужны python3, iverilog, vvp
python3 tests/audit/run_audit.py .

# Создать проект Vivado и открыть GUI, исходный IP создан в Vivado 2023.2
make deploy

# Нужны Verilator, SDL2 dev, sdl2-config и C++-компилятор
cd src/sim
make
./obj_dir/audio
```

`make deploy` не строит и не прошивает FPGA автоматически. Повторный запуск пересоздаёт папку `vivado`: сохраняйте настройки в Tcl и исходниках. [Зависимости](doc/DEPENDENCIES.md).

## Что показали проверки

- FIFO: 20000 тактов с заполнением, опустошением и случайными одновременными операциями — успешно.
- DDS: A4 в шкале выходных сэмплов и удержание фазы при backpressure — успешно.
- PWM и управление кнопками — успешно в проверенных сценариях.
- Дефект: reset не включается повторно при потере PLL lock.
- Дефект: VS VGA смещён относительно заданного front porch.
- Исходный тестбенч не проходит элаборацию Icarus из-за отсутствующих VGA-сигналов при `.*`.

**Текущий аудит специально воспроизводит два дефекта. Его успешный выход не означает, что они исправлены.** Для проверки исправлений потребуются регрессионные тесты правильного поведения.

## Оборудование

Цель: `xc7a100tcsg324-1`, моно-аудио, `AUD_PWM` как 0/Z, sample rate около 48006,5 Гц, 10-битный PWM. Клавиатура по фото определена как Arturia MicroLab mk3. Штатный USB Host платы поддерживает Boot HID клавиатуры и мыши; Поддержка MIDI через J5 в текущем проекте не реализована; поведение фактической PIC24 firmware не измерено. Целевая схема: MicroLab → USB-MIDI host → FPGA wavetable → MONO AUDIO OUT → наушники. В документированной стандартной схеме PIC24 не реализует MIDI host; применимость к учебному экземпляру нужно проверить. При стандартной разводке FPGA RTL не имеет прямого доступа к USB D+/D− J5. [Подробности и необходимое оборудование](doc/DIRECT_USB_MIDI.md).

Предлагаемый порядок: рабочий исходный стенд → сброс/CDC/тестбенч/VGA → общий тракт sample/valid/ready → музыкальный источник по критериям → интерфейс и периферия → проверка на плате и защита.

Пошаговый журнал подготовки и проверки физической платы, включая подтверждённые статусы Vivado и следующий тест звука, находится в [doc/BOARD_BRINGUP.md](doc/BOARD_BRINGUP.md).

Для игры на Arturia MicroLab mk3 через временный ноутбучный USB-MIDI→USB-UART мост смотрите [doc/MIDI_BRIDGE.md](doc/MIDI_BRIDGE.md). Новый RTL уже проходит Icarus-тест, но нуждается в Vivado-сборке и проверке на физической плате.
